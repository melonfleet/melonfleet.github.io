Flotilla · by melonfleet

Apple’s containers, with a window.

Apple shipped container for macOS and left it on the command line. Flotilla is the native app on top: containers, images, volumes, networks and the virtual machines they run inside — plus a real terminal in every container. Free, no account, no telemetry.

Requirements & install Why melonfleet

What it does

Everything goes through Apple’s own container CLI. Flotilla builds and validates every command before it runs, and shows you the exact one it used — nothing happens that you could not have typed yourself.

01

Run and watch

Start, stop, restart and delete containers, with live CPU, memory, ports and addresses. Logs from every source in one feed you can filter.

02

Shell straight in

A real terminal inside any running container, and inside the virtual machines themselves. No docker exec incantation to remember.

03

Everything else, too

Images, volumes, networks and machines — build, pull, prune, create and inspect, from a menu-bar icon or a full window.

Requirements

Two things, and Flotilla tells you plainly when either is missing rather than showing you an empty list.

macOS 26 or later

On Apple silicon. Apple’s container runtime needs both, so Flotilla does too.

Native app

Apple’s container CLI

Install it from apple/container. Flotilla drives that tool — it does not bundle or replace it, and it starts the runtime for you if the service is not running.

Free

Nothing else

No account, no sign-in, no telemetry, no subscription. Signed and notarised by Apple, so it opens without a Gatekeeper argument.
